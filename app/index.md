## 代表项目

### 1. Abox Note｜跨平台 Markdown 笔记应用

**技术栈：Flutter、Dart、Rust、SQLite、Axum、SeaORM、flutter_rust_bridge**

面向移动端的轻量 Markdown 笔记产品，围绕快速记录、本地内容管理、编辑体验与数据可持续使用进行研发。

- **移动端研发：** 使用 Flutter 构建应用界面与交互，持续处理编辑器、键盘、选区、浮层等移动端体验问题。
- **跨语言集成：** 通过 `flutter_rust_bridge` 将 Flutter 客户端与 Rust 核心逻辑连接，将部分数据和业务处理放在共享引擎中。
- **本地数据：** 使用 SQLite 管理笔记数据，设计笔记标识、元数据、附件及历史版本结构。
- **版本历史：** 支持基于完整内容与差异补丁的历史记录，并通过历史重建逻辑恢复笔记内容。
- **数据 API：** 使用 Rust、Axum 提供本机 Data API，包含变更记录、修订及附件相关接口，便于客户端之外的程序访问本地数据。
- **跨平台交付：** 维护 Android、iOS 及桌面端的构建与发布流程，涉及安装包构建、版本更新和平台发布配置。

这个项目体现了从移动端交互、数据模型、核心逻辑到跨平台构建的完整产品研发能力。

### 2. DaoBox｜桌面知识库与内容管理工具

**技术栈：Electron、Rust、SQLite / 文件系统、Git、libgit2、WASM**

面向本地 Markdown 文件的知识库工具，集成内容编辑、知识管理、版本控制与发布能力。

- **桌面端工程：** 使用 Electron 构建跨平台桌面应用，并通过独立 Rust sidecar 承担部分核心服务。
- **本地优先：** 围绕文件系统组织内容，处理 Markdown 文档、附件、内部链接及知识结构。
- **版本管理：** 基于 `libgit2` 集成状态查看、差异检查、提交、同步及冲突读取等 Git 操作。
- **核心能力集成：** 将内容发布引擎、Rust 服务和 WASM 模块整合到桌面应用中。
- **跨平台构建：** 维护 Linux、Windows、macOS 相关组件与应用安装包的构建流程。

项目中的版本控制与同步能力以 Git 工作流为基础；复杂冲突仍需结合具体数据类型和操作流程处理，并非所有冲突都能自动解决。

### 3. Everkm 账号与内容服务

**技术栈：Rust、Axum、Tokio、SeaORM、OAuth 2、PostgreSQL、Redis**

为自有产品构建配套的账号与内容服务，支持多个产品之间的服务集成。

- **账号登录：** 实现 Google、GitHub OAuth 登录相关服务与路由。
- **后端 API：** 使用 Axum、SeaORM 构建服务接口及数据库访问逻辑。
- **服务集成：** 将账号服务与自有内容产品连接，处理登录回调及跨服务访问流程。
- **部署工程：** 维护服务构建与部署相关配置，理解反向代理、多域名服务及前后端协作的基本流程。

项目侧重证明后端 API、第三方身份认证与产品服务集成能力，不将其包装为成熟的企业级身份平台。
